# 威力彩模型評估

先讀專案根目錄的 `docs/model-review-history.md`，找到各區現役、候選、封存清單、上次資料截止期與下一次判定條件。近八年訓練、近一年報表、三種選號及機率調整見 `docs/specs/rolling-eight-year-validation.md`。核對 CLI、設定、實驗產物與前瞻帳本，確認哪些方案已能出號。

## 每輪檢查

1. 依台北日期記錄報表日、資料最新期、帳本截止期、已結算與待結算期數。檢查快照、版本、登記時間、預測對應的實際開獎日及命中數。列出漏登、逾時、重複與勘誤。相同輸入及方案狀態已評過就沿用原紀錄。資料訂正時保留前次結論，追加更正及原因。
2. 歷史比較使用相同目標期、資料快照及計分規則，重播各版實際出號流程。v1 每期用當時全部歷史重訓；舊 265 期封存測試只訓練一次。v2 每期限定過去八年。規格尚待實作時，標「待實作」並記下下一個可驗收項目。歷史重播用來挑值得追蹤的候選，開獎前已登記的共同期數才用來決定換版。
3. 各區分開對同一期計算「候選命中數減現役命中數」。第一區報平均每期多中幾個，第二區報各自命中幾期、共同分母及命中率差。附歷史頻率及均勻選號的理論平均。若比較機率，取每期全區號碼的 Brier score，差值用現役減候選，正值代表候選較好。缺完整分數時標「無法評估」。選號與機率可各自決定留用版本。
4. 每四週查看進度，近一年成績供觀察。正式比較於開獎前登記兩個版本、參與區域、每區一個主要指標、實用改善幅度、起始期、結束條件及區間算法。若探索過多個模型或選號策略，先用回測每區選出一個挑戰者，再開始前瞻登記。模型、權重或視窗一改就另立版本。

## 怎麼下決定

有事前登記則沿用登記規則。首次試行建議每區取登記後最早 **104 個雙方都事前出號且已結算的共同期數**，只在滿期後判定一次。四週的進度報告不重開檢定。104 期是作業預設，微小效果可能需要更多期數。留意缺漏是否集中在特定方案或期間，有選擇偏差時須釐清後再決定。

用專案的逐期配對 bootstrap（10,000 次，seed 2026）估計平均差的 95% 區間。區間下限高於事前登記的實用改善幅度（預設 0）才改用候選。區間跨門檻則留用現役，滿期後結案；期數不足就繼續收集。若整個區間都低於門檻，封存候選，記錄這次落敗的區域與期間。區間是操作依據，交代訓練資料重疊、樣本數及多輪嘗試對解讀的限制。

成效落後時，根據一個具體現象提出一個可推翻的改進假設。寫明只改哪個因素、預期改善哪區與哪個指標、對照版本，以及何種結果會放棄。查封存清單有沒有相同實驗。新方案先走重播，再登記前瞻比較。

## 如何恢復舊版

保留版本 ID、可執行的程式提交或快照、設定與雜湊、特徵與種子、資料範圍、環境、逐期結果及採用或停用理由。恢復前用原設定重現一筆已知選號。缺少還原材料就記明缺口。

若封存的 A 仍同步出號，且 A 與現役 B 已事先登記這場比較，使用該比較的共同期數。若 A 已停止出號，先重播同一段歷史，值得再試就恢復 A 的平行登記。A 與 B 在新一期開獎前各交一組答案，適用同一換版條件。A 勝出時記「恢復 A」並連回原版。過往不同年份的最高分只作為重驗理由。

## 留下紀錄

每次有新證據或決策，將日期、資料識別、各區的現役與候選、證據類型、共同期數、效果差與區間、門檻、決定、理由及下一次判定條件追加到 `docs/model-review-history.md`。封存及復用連回舊決策。分別記錄「評估選定版」和「實際出號版」，核對下一筆正式登記後才標為切換生效。提交、發布及更動正式出號設定依當次授權執行。用繁體中文先說本次留誰，再說證據和下一次要等什麼。
