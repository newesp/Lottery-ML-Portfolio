# 近八年訓練與近一年逐期驗證

實作規格 · 2026-11-25

## 日期怎麼算

目標是衡量每期實際出號時，模型、歷史頻率、混合選號各能猜中幾個號碼，並檢查模型給的機率準不準。採用兩個會移動的日期範圍，以台北當地日期及實際開獎紀錄為準。

| 用途 | 日期規則 |
|---|---|
| 選出要對答案的期數 | 給定報表日期 D，取上一年同月同日至 D 當天之間已公布結果的期數，包含兩端。報表註明資料實際更新到哪一期。 |
| 預測某一期 T | 取 T 往前推八個曆年至 T 前一天的已知開獎資料。包含起日，排除 T。歷史回測每往前走一期就重新切一次、訓練一次，上線預測也使用同一條規則。 |

例如報表日期是 **2028-10-01**，就統計 **2027-10-01 至 2028-10-01** 已開獎的期數。假設目標開獎日是 **2028-09-28**，只能用 **2020-09-28 至 2028-09-27** 的資料。到了下一個預計開獎日 **2028-10-02**，改用 **2020-10-02 至 2028-10-01** 當時已公布的資料。報表日期可以落在沒有開獎的日子。

「2018 年開始、訓練到 2025 年底」對應到目標日 2026-01-01 的八年範圍。日期會隨每個目標日移動。要重播完整的一年，來源資料通常要往前涵蓋約九年，讓最早那一期也有八年可用。若週年日在目標年份沒有對應日期，取該月最後一天。歷史覆蓋不足時，標示缺少的期間與略過期數。輸入須通過既有資料驗證。

已對過答案的期數可加入後續期數的訓練。模型設定、排名權重及機率調整規則在回測前定版。若依回測結果修改規則，另立版本，以後續開獎前登記的結果評估新版。歷史回測採具版本的資料快照，資料事後勘誤可能影響重播結果。

## 每一期的選號與機率

1. 在 Python 新增共用的單期預測入口。先按目標日期裁切原始開獎紀錄，再用現有特徵產生器建立訓練列和下一期候選列。累積次數、間隔、近期頻率等狀態均從八年起點重建。每筆訓練列的特徵也只能讀取該筆以前的開獎。
2. 兩區沿用已凍結的模型、特徵組和三個隨機種子。每期每區訓練一次三模型集成，並取各號碼的平均分數供排序和機率評估共用。
3. 每區產生三張選號清單。**模型**依模型分數排序。**歷史頻率**依窗內出現次數排序。**混合選號**取兩份名次的平均，由小到大排列。兩份原始排名遇同分取平均名次，決定最終入選號碼時若仍同分，取較小的號碼。使用完整精度排名。第一區各取六個，第二區各取一個。
4. 保存每個候選號碼的原始模型分數及調整後機率。第一版將原始機率向量投影至每項介於 0 和 1、總和等於該區開出顆數的集合，採平方距離最小的解。第一區總和為 6，第二區為 1。這項調整讓機率符合開獎規則；其準確度仍須對答案檢查。模型與混合選號使用原始分數排名，以免調整產生的同分改變選號。

## 結果如何計分

- 每一期、每一區記錄三種方法各自選出的號碼、實際命中數與日期。第一區主指標是每期平均命中數，第二區顯示命中期數、已結算期數與命中率。三種方法只在都有預測且已結算的同一批期數上比較。列出待開獎、資料不足及缺漏筆數。
- 逐期相減，計算混合選號相對於模型、相對於歷史頻率的平均命中差。沿用現有按期配對的 bootstrap 呈現描述性 95% 區間，註明相鄰期共用大量訓練資料的限制。隨機選號的理論平均為第一區 36/38 個、第二區 1/8 個。
- 兩區分開計算原始、調整後與均勻機率的 Brier score（預測機率與實際 0 或 1 的平均平方差，愈小愈好）。依事前固定的 10 個等寬機率區間，比較各組平均預測值和實際開出比例，附候選筆數與開獎期數。使用所有候選號碼。

## 四週評估要取得哪些資料

每四週由評估 skill 讀取同一份可重現的比較摘要。Python 負責配對和算分，網站顯示這份摘要，skill 根據事前登記的規則寫下決定。換版門檻的預設值查閱[模型評估 skill](../../.agents/skills/lottery-model-review/SKILL.md)，每場比較保留啟動時採用的值。

| 階段 | 實作要求 |
|---|---|
| 挑候選 | 以相同歷史期數重播現役 v1 與 v2。v1 依原上線流程逐期用全部已知歷史重訓，v2 才使用八年視窗。各區從 v2 三種選號裡挑出一個要正式比較的方案。 |
| 比較開始前 | 建立有版本的比較設定，記下比較 ID、登記時間、第一個合格目標期、區域、現役與候選的版本及方法、主要指標、改善門檻、所需共同期數及區間算法。變更規則另開比較 ID。 |
| 按期結算 | v1、v2 各自保留開獎前的原始預測。以實際目標期與區域配對，核對雙方登記時間與版本。摘要列出資料截止日、證據類型、納入的期別、排除理由、共同期數、兩方成績、逐期差值及其方向。v1 舊帳本第一區只存部分分數，缺完整機率就標「無法比較機率」；要正式比較機率，從雙方開始登記完整分數的期別起算。 |
| 滿期判定 | 近一年報表依日期滾動；正式比較從登記的起始期往後累積。跨過報表一年的早期紀錄也要保留。每場比較只對最早滿額的共同期數判定一次。尚未滿期就回報進度；同一輸入重跑應得到同一份結論。 |
| 封存與恢復 | 決策連回比較設定、逐期證據及可重現的程式與設定版本，並記錄評估選定版及實際出號版。要恢復 A，先用原版重現已知選號，再照 skill 的規則和現役同期比較。實際切換日期以正式帳本的第一筆新版預測確認。[決策紀錄](../model-review-history.md) |

## 網頁呈現

- **實驗室**增加「近一年逐期回測」。顯示報表日期、涵蓋期數、最新可用資料日，以及三種方法的同期間成績。點選某一期即可看它實際用了哪八年、猜哪些號碼、中了哪些球。
- **前瞻盲測**每期顯示登記時間、兩區各三組選號。待開獎時顯示狀態，結算後標出命中的球。歷史重播放在實驗室，此頁只統計開獎前已登記的紀錄。
- **評估結果**並列兩區的命中差與機率評估。預測機率對上實際比例，以表格列出各組樣本數。註明第一區每個百分比代表「這顆球入選六個號碼的機率」。三頁讀取 Python 已產生的報表，日期、期數及成績皆由資料帶入。

## 驗收

1. 以 2028-10-01 驗證報表兩端、週末無開獎、跨年與閏日。最新一期尚未公布時，畫面須顯示實際資料截止日，已結算分母只含有答案的期數。
2. 調換目標期或之後的開獎結果，該期選號與機率應逐項相同。修改八年以前的資料也應得到相同結果。訓練起日當天有開獎時應納入。
3. 用同一份窗內資料、同一目標日及設定走回測和前瞻入口，三組號碼及全區分數須逐項相同。測試同分橫跨入選邊界，驗證每區號碼數量、範圍及唯一性。
4. 驗證兩區機率合計的誤差小於 10⁻⁹，每項落在 0 到 1。用可手算的小樣本核對命中數、均方誤差、機率分組與分母。
5. 同一快照重跑應重現逐期結果。測試快取失效、跨年度移出報表的舊期數、前瞻重跑及舊帳本讀取。網站需能呈現零期、待開獎及已結算三種狀態。
6. 用含漏登、逾時和歷史重播的測試資料核對正式比較的分母。以 104 期的測試設定驗證第 103 期仍在收集，第 104 期才判讀，第 105 期不改寫原決策。讓最早一筆落在近一年報表之外，確認它仍算入正式比較。
7. 模擬 A 封存後重返比較，能從舊紀錄找到原設定、重現已知選號，並追到這次恢復所依據的共同期別。若評估已選定 A 但仍由 B 出號，兩個狀態須可辨識。

## 執行與查核

在此 checkout 安裝專案後，執行 `lottery-ml experiments walk-forward --as-of 2026-11-25` 可重建整年報表。要量測耗時可加 `--limit 2 --output .rolling-cache/pilot.json`。報表會列出可用期數、實際計算期數與略過原因。每期完成後，訓練資料、版本、設定及環境相同的預測可直接從快取讀回。

資料更新排程先執行 `forward predict` 及 `forward predict-v2`，登記完成後才更新歷史回測。單獨執行 `forward summarize-v2` 可從帳本重新結算。四週評估讀取以下產物。

- [回測報表](../../artifacts/experiments/walk-forward-v2.json)記錄每期的訓練範圍、各版本的選號、答案及機率分組。
- [前瞻摘要](../../artifacts/forward/v2/summary.json)列出登記、錯過期限的目標日、正式比較的排除原因、估計差與實際出號版本。前瞻頁顯示最近一次正式採用的號碼及各區的方法。正式比較尚未登記時，兩區各自的有效比較期數為零。
- [出號設定](../../configs/experiments/forward-methods.json)指定要平行執行的 rolling 版本，以及各區實際採用的方法。更新設定後，只有在截止前取得該期兩區的已登記選號，才會寫入正式出票紀錄。

從回測挑好候選後，在第一期預測前執行 `lottery-ml forward register-comparison`。例如比較第一區命中數時，可指定 `--id area1-mixed-round1 --area area1 --metric hits --incumbent forward-v1/model --candidate rolling-v2/mixed --first YYYY-MM-DD`，日期填入預先選定的未來期別。`--count` 與 `--margin` 可在登記時調整；登記後設定以只寫一次的檔案保存。比較機率時使用 `--metric brier`，方法填 `raw` 或該版本提供的 `adjusted`。有漏登或套件版本變動時，摘要會標出受影響期別，供採用結論前核對。

要恢復舊方案，先在對應程式與套件版本下執行 `lottery-ml experiments verify-entry --entry <舊版逐期登記檔> --dataset <當時資料快照>`。此指令核對 rolling 版本的身分、資料指紋、選號及完整分數。重開比較時，可用 `--candidate-entry` 或 `--incumbent-entry` 指向該筆登記，固定對應的歷史版本。不同演算法使用不同協定 ID；舊版若需要獨立執行環境，由該環境以相同帳本根目錄執行 `forward predict-v2 --protocol <協定 ID>`。正式換版與否另記入[評估紀錄](../model-review-history.md)。
